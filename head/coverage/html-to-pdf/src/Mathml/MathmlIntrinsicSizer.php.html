11/**
12 * Measure an inline `<math>` subtree during LAYOUT.
13 *
14 * {@see MathmlRenderer::intrinsicSize()} could always do this, but its
15 * only caller was the painter — which runs after layout has already
16 * placed every box. So layout sized the `<math>` atomic inline at 0x0
17 * and the painter then drew a correctly-sized equation into a box that
18 * reserved no room for it: content after an equation overprinted it,
19 * and a line holding nothing but math collapsed to the height of an
20 * empty text line.
21 *
22 * `BlockLayout` consults this from its inline-atomic pre-pass, which is
23 * the same point where an `inline-block`'s used content size is
24 * resolved, so the result flows into the existing `laidOut*` protocol
25 * without `InlineLayout` needing to know MathML exists.
26 *
27 * ### The scratch writer
28 *
29 * `MathmlRenderer` takes a page and a writer because it normally
30 * paints. Measuring touches neither — it only needs the two standard
31 * faces to exist so the paint context can be constructed. Layout has no
32 * page yet (pagination creates them later), so this holds a scratch
33 * `PdfWriter` whose output is discarded. It is created lazily and
34 * reused, so documents without MathML pay nothing at all and a document
35 * with many equations pays for one throwaway writer.
36 *
37 * The parsed-document cache is shared with {@see InlineMathmlAdapter} by
38 * passing the painter's adapter in, so a `<math>` measured at layout and
39 * painted afterwards is parsed once rather than twice.
