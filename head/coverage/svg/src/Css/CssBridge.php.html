21/**
22 * Bridge between an SVG element tree and the `phpdftk/css` cascade.
23 *
24 * `computeStyle()` resolves the effective CSS values for one element by
25 * layering, in increasing precedence:
26 *
27 *  1. SVG presentation attributes — author origin, specificity 0,0,0,0
28 *     per SVG 2 §6.7. Synthesised into a one-rule stylesheet with a `*`
29 *     selector so it matches but doesn't out-rank anything.
30 *  2. `<style>` element CSS from the document — author origin, normal
31 *     selector specificity per Selectors 4.
32 *  3. The element's inline `style=""` attribute — author origin,
33 *     specificity `(1024, 0, 0)` per CSS Cascade 5 §6.4.4. The `Cascade`
34 *     reads this directly from `MatchableElement::getAttributeValue`
35 *     so we don't need a manual overlay.
36 *
37 * The bridge depends on `phpdftk/css`. It lives in its own namespace so
38 * loading `Phpdftk\Svg\Element` doesn't transitively pull the CSS
