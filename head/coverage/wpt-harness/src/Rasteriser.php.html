7/**
8 * Renders a PDF to a PNG file for downstream perceptual diffing.
9 *
10 * v1 implementation: shells out to Ghostscript with `-sDEVICE=png16m`
11 * at the configured DPI. One PNG per page; this method returns the
12 * path for `$pageIndex`.
13 *
14 * The default is **72 dpi**, which makes one device pixel one PDF
15 * point and — because the renderer emits 1 CSS px as 1 pt — one CSS
16 * pixel. That is the geometry WPT reftests are written against, where
17 * the browser runs at one device pixel per CSS pixel.
18 *
19 * Sampling denser than that looks free, because a reftest compares two
20 * renders that scale together, but it is not: a fixture's
21 * `<meta name="fuzzy">` `totalPixels` bound is an ABSOLUTE count of
22 * differing pixels, chosen by its author against a 1:1 browser. The
23 * harness used to rasterise at 96 dpi, where a CSS pixel covers
24 * (96/72)^2 = 1.78 device pixels, so every declared budget was being
25 * asked to cover 1.78x the pixels it was written for and fixtures
26 * failed on arithmetic rather than on rendering.
27 *
28 * Resolution decides more than the budgets, because it decides which
29 * coordinates are fractional. At 96 dpi an integer CSS coordinate
30 * lands on a device pixel boundary only when it is a multiple of
31 * three; at 72 dpi it always does, which keeps whole-pixel CSS
32 * geometry off the rounding boundary entirely. See
33 * {@see self::fillAdjustPrologue()} for what happens at that boundary.
34 *
35 * v2 implementation (Phase 4C): swap to `phpdftk/raster` so the
36 * harness has zero external dependencies. Until then the gs path
37 * is the canonical implementation.
38 */
